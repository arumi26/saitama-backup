## Architecture
- Diamond-like account model: `FortyAcresPortfolioAccount` delegates to facets via `FacetRegistry`.
- `PortfolioFactory` creates accounts with CREATE2; `FacetRegistry` maps selectors → facet addresses.
- Core loan logic in `LoanV2.sol`; vault logic in `LendingVault.sol` and `DynamicFeesVault.sol`.
- `PortfolioLoanLib` handles portfolio-scoped loan operations.

## Candidate Findings

### HIGH — Unauthorized cross-portfolio debt state manipulation
- `LoanV2.payFromPortfolio()` / `borrowFromPortfolio()` only check `IPortfolioFactory.ownerOf(msg.sender) != address(0)`.
- They do **not** verify that the caller is the borrower of the specific loan being modified.
- Impact: any portfolio holder can reduce/increase `_outstandingCapital` and vault debt balances for loans they do not own.
- Files: `src/LoanV2.sol:1311-1324`, `src/PortfolioLoanLib.sol:57-111`
- Sherlock scope includes `LoanV2.sol`.

### HIGH — Unauthorized borrow creation via portfolio
- Same root cause as above: `borrowFromPortfolio` lacks entity binding to a specific loan.
- Attacker with any portfolio can create debt against the vault, increasing `totalLoanedAssets` and `debtBalance[msg.sender]`.

### MEDIUM-HIGH — Single-owner instant facet upgrade
- `FacetRegistry.replaceFacet()` is `onlyOwner`, no timelock/multisig.
- One key can replace all facets for every account instantly.
- Files: `src/accounts/FacetRegistry.sol:117-145`
